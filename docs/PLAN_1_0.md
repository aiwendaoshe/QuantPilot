## 0. 一句话结论

**工程骨架优秀、选股/回测主链路可用；但"专业度"目前有一半是装饰**——7 因子评分雷达是空壳、资金流向/板块热度无真实数据、无自选股、无市场情绪、无板块/行业模块。1.0 的核心任务不是堆功能，而是**把"伪专业"变成"真专业"**，并补齐操盘手日常离不开的四个工作台（板块、情绪、自选、回测报告）。

## 1. 当前架构与技术现状（基于代码实查）

### 1.1 技术栈与分层（架构师视角：优）

| 维度 | 现状 | 评价 |
|---|---|---|
| 分层 | shared（类型/常量）/ main（ipc-router 单入口 + services + providers + workers）/ preload（plainify 防 DataCloneError）/ renderer（views/stores/components） | ✅ 清晰，主子铁律执行到位 |
| 类型安全 | TS strict；IPC 请求/响应双向类型；`DbStatus` 等 DTO 五处同步校验 | ✅ 扎实 |
| 选股引擎 | 7 策略 + 指纹缓存（内存 + meta 双级）+ 并发锁前置 + `force` 失效 | ✅ 切页不重算，体验好 |
| 回测纪律 | T+1、末根 `endOfData` 强平、无未来函数 | ✅ 专业底线守住了 |
| 数据诚实 | `meta.dataSource` / `engine` 字段显式标注，禁用 mock 冒充 | ✅ 治理到位 |

### 1.2 数据层（诚实评估：有单点风险）

- 三 Provider：**sina / tdx / tencent**，能力 = `universe / snapshot / dailyBars`。
- `dailyBars` **锁死腾讯**（`LOCKED={dailyBars:'tencent'}`），腾讯限频/改版即全瘫，无降级兜底。
- 数据库仅 3 表：`stocks(code,name,industry,market)`、`daily(OHLCV)`、`meta(kv)`。
- `amountCoverage` 历史恒为 0（历史 amount 缺口未回填，已诚实标注但未修）。

### 1.3 功能现状盘点（操盘手视角：虚实对照）

| 模块 | 现状 | 虚实 |
|---|---|---|
| 选股（7 策略） | 均线多头/趋势/断板反包/N字反包/海龟突破/均线放量/上升跌停反包 | ✅ 真实可跑 |
| 综合评分 `score` 0-100 | 策略内计算 | ✅ 真实 |
| **7 因子雷达 `breakdown`** | **已接通**：7 策略全调 `computeBreakdown` 并挂到 signal，`StockCard` 条件渲染、`buildRadarOption` 映射 7 轴（实测多头样本 trend/strength=100、score=73；横盘 trend=0、score=35，区分度正常） | ✅ 雷达能画 |
| **资金 `fund` / 板块 `sector` 因子** | `scoring.ts` 注释已自陈为**价格派生代理值**（非真实主力净流入/板块指数），但轴标签仍写"资金/板块" | ⚠️ **标签误导（伪专业点）** |
| 资金流向因子 `fund` | 无 moneyflow 数据，未计算 | ❌ 装饰 |
| 板块热度因子 `sector` | 仅 `industry: series.meta.industry` 标签化 | ❌ 装饰 |
| 行情浏览 Market | "A股行情"原始表（搜索/排序/点开个股） | ⚠️ 非情绪看板 |
| 涨停板 LimitUp | 空态提示"点增量更新" | ⚠️ 弱 |
| 个股详情 StockDetail | K 线 + 信号标记 | ✅ 但无"加自选"按钮 |
| 回测 Backtest | 指标卡 + 权益曲线 + 30 笔成交表 | ✅ 指标真，报告弱 |
| **自选股** | 无（StockDetail 无加自选，pullRunner 仅注释提及） | ❌ 缺失 |
| **板块/行业模块** | 无（industry 仅个股标签） | ❌ 缺失 |
| **市场情绪** | 无（涨跌家数/连板高度/情绪指数均无） | ❌ 缺失 |

### 1.4 必须正视的硬伤

1. **资金/板块因子标签误导（伪专业点）**：雷达能画，但 `fund`(资金) 轴实为「近 5 日 (close-open)/open 之和」、`sector`(板块) 轴实为「个股当日涨幅映射」——皆价格派生代理值（scoring.ts 已注释自陈），轴标签却写"资金/板块"，对操盘手构成误导。M1 已做透明化标注，真实板块热度待 M2 接入板块数据后替换。
2. **资金/板块真实数据为零**：A 股短线第一生产力是"题材轮动 + 资金合力"，目前两因子全靠代理，无真实主力净流入 / 板块指数。
3. **四大陆缺失**：板块、情绪、自选、回测报告，全是操盘手每日必看，当前要么没有要么弱。
4. **数据单点 + 历史缺口**：腾讯锁死 + amount 恒 0，极端行情下数据可信度打折。

## 2. 1.0 目标定位

> **从"能选股的工具"升级为"短线操盘工作台"**：板块找方向 → 情绪定仓位 → 自选做跟踪 → 策略出信号 → 回测验真伪。

原则：**每个展示指标都必须有真实数据支撑或明确标注"估算"**，绝不留伪专业。

## 3. 模块详细规划

### M1 · 评分雷达"去伪存真"（地基，✅ 已完成 P1 首刀）
- **核查结论（修正早期误判）**：雷达本就接通（7 策略全调 `computeBreakdown`，UI 条件渲染），并非空壳；真正问题是 `fund`/`sector` 两轴是价格派生代理值却标"资金/板块"。
- **已做**：
  1. `StockCard.vue` 雷达下方加注「资金·板块为价格派生估算值，非真实主力净流入 / 板块指数」→ 透明化去伪。
  2. `aggregate.ts` 多策略命中同票时，雷达 `breakdown` 跟随最高分那条策略，避免展示与评分错配的旧雷达。
  3. 功能实测：`computeBreakdown` 对多头/横盘样本产出有区分度数值（73 vs 35），数学正确。
- **留待 M2**：真实板块热度（板块涨幅榜接入后，用个股所属行业当日均涨幅替换 `sector` 代理）。资金流真实数据 1.0 暂不在计划内（无对应数据源），维持透明标注。

### M2 · 板块 / 行业模块（找方向） ✅ 已完成
- **目标**：板块涨幅榜 + 板块详情 + 板块热度反哺评分。
- **数据需求**：新增 Provider 能力 `sector`（板块列表/涨幅/领涨股/成份股）、`concept`（概念）。候选源：新浪板块接口（历史验证可用）、腾讯板块。
- **实现**：
  1. 拉取全板块当日涨幅、领涨股、成交额，存新表 `sectors`。
  2. 板块列表页（按涨幅/资金排序）、板块详情页（板块内个股 + 与大盘联动）。
  3. 板块热度 → 喂 `sector` 因子，让雷达"板块热度"变真。
- **验收**：能按板块浏览、能看到板块内候选股、评分 sector 因子有值。

### M3 · 市场情绪看板（定仓位） ✅ 已完成
- **目标**：每日情绪量化，辅助仓位决策。
- **数据**：**本地可算**（daily + stocks），无需新源。涨停/跌停识别 = 当日涨跌幅 ≥9.5%（剔除 ST）；连板 = 连续涨停计数。
- **实现**：
  - 情绪指标卡：涨停家数、跌停家数、涨跌家数比、连板高度榜、昨日涨停今表现、全市场量能。
  - "情绪温度计"（综合打分 0-100）+ 历史曲线（按日存档 `sentiment_daily`）。
  - 与 Market 视图解耦：Market 仍是行情表，情绪单独成页。
- **验收**：开盘/收盘后能看当日情绪全貌 + 历史趋势。

### M4 · 自选股工作台（做跟踪） ✅ 已完成
- **目标**：加自选、分组、监控、用策略扫自选池。
- **数据**：新表 `watchlist(code, group, note, added_at, cost_price?)`。
- **实现**：
  1. StockDetail 加"加自选/移出自选"；支持分组（如"观察/持仓/已清"）。
  2. "我的自选"页：列表 + 实时涨跌幅 + 所属板块 + 是否触发某策略信号。
  3. 一键"仅对自选池选股"（`runScreener` 已支持 poolLimit，扩展 `scope:'watchlist'`）。
  4. 可选：成本价 → 浮动盈亏（需用户录入，非券商账户）。
- **验收**：能加、能分组、能只在自选里选股、能看信号命中。

### M5 · 回测报告增强（验真伪） ✅ 已完成
- **目标**：从"指标卡"升级为"可决策的报告"。
- **实现**：
  - 分年/分月收益表、持仓期分布直方图、最大回撤区间在权益曲线上标注。
  - 参数敏感度（网格扫描，复用 `meta.paramSchema` 驱动）。
  - **导出**：交易明细全量 + 权益曲线 → CSV/Excel（可借 tencent-docs-sheet 或内置 csv）。
  - 多策略横向对比（同区间胜率/回撤/夏普并列）。
- **验收**：能导出、能看回撤发生在哪段、能比多策略。

### M6 · 数据韧性（兜底） ✅ 已完成
- **目标**：解除单点，修历史缺口。
- **实现**：
  - `dailyBars` 允许 breaker 切换 sina/tdx 兜底（保留 tencent 默认，故障时自动降级）。
  - 历史 `amount` 缺口回填（腾讯 qfq 端点已证伪"no-data 集中在除权股"旧归因，可安全回填）。
  - `DbStatus` 增加降级指示，UI 明示"当前数据源"。
- **验收**：腾讯故障时自动切源不崩；amount 覆盖率提升。

## 4. 实施路线（建议分三阶段）

| 阶段 | 模块 | 依赖 | 产出 |
|---|---|---|---|
| **P1 夯实** | M1 雷达去伪 + M6 数据韧性 | 无 | 专业度可信、数据不断供 |
| **P2 四大工作台** | M2 板块 + M3 情绪 + M4 自选 | M1（sector 因子） | 操盘日常四件套 |
| **P3 决策增强** | M5 回测报告 + 多策略对比 | 无 | 信号可验证 |

> 优先级建议：**M1 → M4（自选，高频刚需）→ M3（情绪）→ M2（板块）→ M5 → M6**。
> 理由：M1 是地基（修信任），M4 成本最低收益最高，M3 本地可算零数据依赖，M2 最重（需新数据源评估）。

## 5. 风险与取舍

1. **板块/概念数据源**：新浪板块接口历史可用但需重新验证 CORS/限频；若不可用，M2 降级为"按 industry 标签聚合"（已有数据，弱但有）。
2. **资金流向 realtime**：新浪/腾讯有逐笔/主力资金接口但稳定性待验，M1 阶段不强行做，先留"估算"标注。
3. **范围控制**：1.0 不做券商账户直连（合规 + 主子模式是无账户只读），自选盈亏靠用户录入成本价。
4. **沙箱限制**：Electron GUI 起不来，所有 UI 改动仍靠 headless Chrome + CDP + 三套 typecheck 验证，真机观感需主子验收。
